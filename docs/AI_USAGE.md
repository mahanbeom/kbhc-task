# AI_USAGE

Agent AI 활용 내역입니다. requirement.md의 필수 4항목(도구/모델, 작업 범위,
핵심 프롬프트 요약, 사람이 최종 검증한 내용)과 선택 항목(계획 문서,
subagent 설정)을 담았습니다.

## 1. 사용한 도구/모델

- **Claude Code (데스크톱 앱)** + **Claude Fable 5**
- **Subagent는 code-reviewer 1개만 정의** ([.claude/agents/code-reviewer.md](../.claude/agents/code-reviewer.md)) —
  구현이 끝난 코드를 독립 컨텍스트에서 검증만 하는 읽기 전용 에이전트 사용.
  컨텍스트 파편화로 일관성이 흐트러지지 않도록 역할이 명확한 검증 전용 에이전트 하나로 절제.
  슬라이스 2(인증 코어)와 슬라이스 6(최종) 두 번 실행.

## 2. 적용한 작업 범위

| AI가 수행                               | 사람이 수행                             |
| --------------------------------------- | --------------------------------------- |
| 채용 공고·과제 요구사항 분석            | 기술 스택 방향 제시와 최종 선정         |
| SPEC.md 초안·자의적 결정 8건 정리       | 각 결정의 검토·합의·승인                |
| 구현 계획(수직 슬라이스 7개) 수립       | Plan mode에서 계획 검토·승인            |
| 슬라이스별 구현·테스트 작성(TDD)        | 슬라이스마다 결과 확인 후 커밋 승인     |
| 브라우저 실구동 검증(네트워크·DOM 실측) | 검증 시나리오·기준의 타당성 확인        |
| docs/tasks/TASK_0~6.md 작업 기록        | 기록의 정확성 검토(오판 정정 지시 포함) |
| code-reviewer 리뷰 실행·지적 사항 수정  | 리뷰 결과 설명 요구·반영 방향 결정      |

**진행 프로세스**: 슬라이스 수행 및 결과 기록(AI) → 수행 결과 검증 및
피드백(사람) → 피드백 반영 및 결과 기록(AI) → 반영 결과 검증 및 커밋
지시(사람) → 커밋 후 다음 슬라이스 수행(AI).
AI는 구현·문서화를, 사람은 검증·피드백·승인을 반복합니다.

## 3. 핵심 프롬프트 요약

세션 간 컨텍스트는 핸드오프 문서로 승계하며 진행했습니다. 주요 흐름:

1. **공고·과제 분석** — 채용 공고와 requirement.md·openapi.yaml을 교차
   분석 지시 → openapi에만 존재하는 `/api/refresh`(쿠키 기반) 플로우가
   숨은 핵심 요구임을 발견.
2. **스펙 수립** — 문서가 정하지 않은 지점(토큰 저장 위치, 미인증 접근
   처리, page size 등)을 "자의적 결정 후보 + 대안 + 근거" 형태로 도출하게
   하고, 8건을 문답으로 합의해 SPEC.md로 고정.
3. **계획 승인** — Plan mode로 수직 슬라이스 7개(스캐폴딩→로그인→인증
   인프라→대시보드→목록→상세/삭제→마감) 계획을 세우게 하고 승인
   ([PLAN.md](PLAN.md)).
4. **슬라이스 구현** — 슬라이스마다 "TDD로 테스트 선행 → 구현 → 검증
   명령 4종 + 브라우저 실구동 → TASK_n.md 기록 → 정지" 루프를 지시.
5. **검토 문답** — 구현 결과에 대해 구조·원리를 캐묻는 질문(아래 4절)으로
   AI의 판단을 검증하고, 틀린 지점은 정정을 지시.

## 4. 사람이 최종 검증한 내용

기능 동작 확인 외에, AI의 판단 자체를 검증해 정정·개선한 핵심 사례입니다.

1. **외부 공유 설정 의존 제거 지시** — 초기 스캐폴딩이 개인 공용 설정
   패키지를 참조하자 제출물의 자체 완결성을 위해 제거를 지시, ESLint/
   Prettier/tsconfig을 저장소 안에서 완결.
2. **AI 오판을 조사로 정정** — msw postinstall 스크립트의 역할을 AI가
   "후원 안내"로 오판한 것을 재조사시켜 worker 동기화 스크립트임을 확인,
   pnpm 빌드 스크립트 정책의 원인 규명과 clean clone 재현 검증을 요구.
3. **테스트 인프라 패치를 구조 결함으로 지적** — 테스트 setup에서 fetch
   URL을 보정하던 1차 해결책을 "테스트가 프로덕션 결함을 덮는 구조"로
   지적 → `shared/api` 기본 계층(base URL 해석의 정식 책임화)으로 재설계.
4. **AI의 반대 근거를 수용해 본인 제안 철회** — MSW 핸들러 경로의
   와일드카드 매칭 제안에 대해 AI가 과잉 매칭 근거로 반대하자 수용.
5. **부트스트랩 refresh 구조 검토** — "첫 접속에 401이 나는 구조가
   맞는가"를 문제 제기, AI에게 전체 인증 흐름 시각화와 대안(lazy 가드,
   힌트 플래그) 비교를 요구한 뒤 현행 유지를 결정.
6. **라이브러리 동작 원리 검증 문답** — react-query의 refetch 트리거
   (visibilitychange·staleTime)와 retry 횟수 의미(`failureCount < 3`),
   `useSuspenseQuery`/`ensureQueryData`의 관계, TanStack Router의
   notFound 라이프사이클 등을 캐물어 구현 근거를 확인. 이 과정에서
   사람이 발견한 `ensureQueryData` deprecated 표시를 계기로 신규 API
   (`queryClient.query`)로 교체.
7. **mock의 계약 타입 미적용을 지적** — 핸들러 응답이 타입 없는 리터럴인
   점을 지적 → MSW 제네릭으로 openapi 계약을 컴파일 타임에 강제하도록
   반영.
8. **문서 정확성 요구** — 작업 기록의 이슈가 "테스트 환경 한정 문제인지
   실제 앱 문제인지" 구분을 요구해 기록을 정정.

code-reviewer subagent의 최종 리뷰 결과(Critical 0)와 지적 사항 반영  
내역은 [tasks/TASK_2.md](tasks/TASK_2.md)·
[tasks/TASK_6.md](tasks/TASK_6.md)에 기록되어 있습니다.
